# ETF 全市场盯盘 + 历史数据

**线上地址：https://etf-board.171098509.workers.dev**

境内上市全部 ETF（1717 只）的实时盯盘页，全部跑在云上：Cloudflare Workers 提供页面，
GitHub Actions 每天收盘后算历史指标，推到仓库的 `data` 分支；Worker 从那里读，边缘缓存 6 小时。

不是本地方案——不需要在你的机器上装任何东西、开任何端口。

## 一、两条链路，互不影响

| 链路 | 数据 | 频率 | 失效影响 |
|---|---|---|---|
| **实时行情** | 新浪全市场 1717 只 / 东财带 IOPV | 5 秒缓存，前端 10~60 秒刷新 | 页面无数据 |
| **历史数据** | `data` 分支上的日线与指标（存 R2 也行，代码两条路都支持），Actions 每天 16:35 更新 | 日更 | 只影响 K 线面板，实时表照常 |

历史那条断了，盯盘照常能用；行情源挂了，历史面板还能看。这是刻意分开的——
免费行情源没有 SLA，把它们绑在一起等于让整页陪葬。

## 二、页面在干什么

| 功能 | 说明 |
|---|---|
| 全市场榜单 | 1717 只，按成交额/涨跌/换手排序，搜索代码或名称 |
| **同指数去重** | 默认每组（如沪深300 的 29 只）只留成交额最大的一只，1717 → 515 |
| 点 `×N` 标签 | 展开该指数全部成员，按成交额排序 |
| 点表格行 | 弹出 K 线面板：近 2 年日线 + 成交量 + 可切换副图 |
| **副图可切换** | RSI14 / MACD / 量比5 / 波动率 / ATR14 / BOLL%B 六选一；主图可叠均线、布林带。深链 `?sub=macd` 直接打开对应副图 |
| 9 张指标卡 | K 线下方跟随游标，给值也给判断（超买/死叉/占价百分比）；当前副图对应的卡会高亮 |
| **因子研究页** | `/research`，独立页面：IC 检验、样本外回测、101 个因子明细、相关性聚类结果 |
| 自选 | 云端同步（Workers KV）。**按浏览器各存一份**，互不覆盖；点「同步」复制带 `?u=` 的链接可在别的设备打开同一份 |
| 涨跌配色 | 红涨绿跌 |

## 三、数据源实测（2026-11，公网环境）

| 源 | 用途 | 实测 | 典型延迟 | 说明 |
|---|---|---|---|---|
| 新浪 `hq.sinajs.cn` | **全市场主源** | ✅ | 35ms | `etf_hq_fund` 节点可翻 18 页拉全 1717 只；**强校验 Referer 必须是 sina 域名**，只能由 Worker 代理 |
| 腾讯 `qt.gtimg.cn` | 自选批量（浏览器直连） | ✅ | 170ms | 88 字段，**无 Referer 校验**，但返回 GBK——Worker 的 TextDecoder 解不了，只能交给浏览器 `<script src>` |
| 东财 `push2delay` | IOPV / 溢价率 | ⚠️ 视网络 | — | `f441`=IOPV、`f402`=折价率；机房 IP 被风控，家宽通常可用 |
| 新浪 `klc_kl.js` | **全历史日线** | ✅ | 80ms | 加密格式，需解码；510300 可回溯 3507 个交易日 |
| 新浪 `getKLineData` | 快速取日线 | ✅ | 50ms | **硬上限 1023 条**，只适合取近期 |
| 天天基金 `jbgk_{code}` | 跟踪指数 | ✅ | 300ms | 1717 只约 75 秒，季度更新一次 |
| 集思录 `etf_list` | 折溢价率 | ❌ | 190ms | 单页固定 20 条、分页无效，不能做生产源 |

**为什么不能纯前端**：新浪校验 Referer、东财校验 CORS，浏览器都直连不了。只有腾讯可以，
但它是 GBK 且只有 A 股口径。所以走「Worker 代理新浪 + 浏览器直连腾讯自选」的混合。

## 四、历史数据与因子

`data/` 里是 153.8 万条日线（1717 只 × 约 3500 天），已经做过复权和份额折算修正。
`alpha/` 在其上算 56 个技术指标和 101 个 Alpha101 因子，`dist/` 是产物。

> **先读 `docs/FACTORS.md`**。里面有逐条公式和直觉，还有一个不太好看的实测结论：
> 这套因子在 ETF 上样本外失效——训练段夏普 1.61，测试段 −0.71，IC 持续性 0.18。
>
> 所以盯盘页**只放技术指标**（MA/RSI/成交量/波动率这些描述性工具）。
> 101 个因子的全部检验结果单独放在 `/research` 页面——留在那儿是为了有据可查，
> 不是为了让你照着买卖。知道它不能干什么，比知道它能干什么更重要。

**因子值每天重算一次。** Actions 每天 16:35 走完 `compute.py`（56 指标 + 101 因子，
全量重算）后，还会跑 `select_factors.py`（相关性聚类 + 样本外回测，约 33 秒）
和 `tools/gen_research.mjs`，把结果压成 5KB 的 `research.json` 推到 `data` 分支。

页面先用手上内嵌的那份立刻渲染（0ms、断网也能看），再向 `/api/research` 要当天的，
拿到就原地替换。所以打开即有内容，数据也不会停在部署那一天。

只有 17 个精选字段（`HIST_FIELDS`）进了历史二进制，其余因子只存在于这张汇总表里——
Parquet 单个文件 2.27MB，每天全量重传 993MB 没有意义，回测在本地重跑 `compute.py` 即可。

技术上有个硬约束值得记一笔：**Workers 免费版 10ms CPU 解不了 Parquet**（单只 2.27MB、
165 列必然超时）。所以历史数据另导一份精简二进制（近 500 天 × 17 字段，34KB/只），
前端 `DataView` 直接读，不需要 wasm、不需要图表库。

## 五、已知限制

- **免费源没有 SLA**。上游按 IP、按接口粒度风控，随时可能失效。不要作为交易决策的唯一依据。
- **Actions 定时任务会漂移**。GitHub 的 schedule 在高峰期可能延迟几十分钟，历史数据不是准点更新。
- **历史数据默认存在 GitHub 仓库**，62MB，不绑卡。想更快可以换 R2（需绑卡开通，额度内不扣费），代码已支持，改一个变量即可。
- **指数映射会过期**。新 ETF 上市后不在表里，按"无跟踪标的"处理（不去重，不会出错）。
  Actions 每天检查覆盖度，低于 90% 会打 warning。
- 溢价率在跨境 ETF 上才有参考意义（QDII 额度紧张时能冲到 5%+），宽基通常贴近 0。
