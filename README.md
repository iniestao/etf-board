# ETF 全市场盯盘 + 历史数据

**线上地址：https://etf-board.iniestao.workers.dev**

境内上市全部 ETF（1717 只）的实时盯盘页，全部跑在云上：Cloudflare Workers 提供页面，
GitHub Actions 每天收盘后算历史指标，推到仓库的 `data` 分支；Worker 从那里读，边缘缓存 6 小时。

不是本地方案——不需要在你的机器上装任何东西、开任何端口。

## 页面结构

- **盯盘（/）**：浅色。自上而下：
  1. 四张统计卡（含「今日诊断信号」）；
  2. **今日变化**：把「相比昨天变了什么」抽成事件——创新高/新低、穿过 80/20 分位、
     量能突变、贴新高 1% 以内、溢价异常。没事件的标的不出现；
  3. **组合体检**：用最近 60 个共同交易日的相关矩阵，把 N 只自选折算成
     「有效独立仓位数」，并给出最像/最不像的两对；
  4. **位置诊断**：每只一张卡，近一年区间位置（RANGE_POS）、20 日路径效率（PE）、
     量能倍数、距高/距低，交叉成动作标签；
  5. **全市场异动**：跳出自己的池子，看全部 400+ 个指数今天谁创新高、谁放量、
     谁破位。一个指数只留流动性最好的那只 ETF，按事件类型筛选，附带市场宽度
     （多少只在一年的高位/低位、中位位置）与十类风格的位置地图；
  6. **急涨急跌**：上一块看「今天」，这一块看「刚才」——过去 3 / 5 分钟谁在
     急拉、谁在急砸，量比跟不跟得上。左急涨右急跌，每边 5 行，带 20 分钟
     迷你走势线；点一行直接打开分时；
  7. 自选表与全市场榜单。

  位置一律以「昨天」为锚（区间取到昨天那根），所以位置差分等于今天真实的位移。
  宽度提示里的「中位位置 16%」是位置百分位取整：位置 =（现价 − 近一年最低）÷
  （近一年最高 − 近一年最低）。它既不是涨幅也不是价格，所以要带 % 并跟左右两边
  的「只数」区分开——留一位小数（15.8）只会让人以为那是某个价位。
  自选相关的三块（今日变化 / 组合体检 / 位置诊断）复用 K 线面板已有的日线 +
  实时快照，不新增行情接口。

  「全市场异动」是唯一需要预计算的一块：`alpha/events.py` 在收盘后随因子一起
  重算，把 400+ 个指数的位置、量能、事件压成 26KB 的 `events.json`，跟着
  `dist/hist/` 目录发布到 data 分支，Worker 用 `/api/events` 读取（边缘缓存
  30 分钟）。快照里带着一年高低点（已换算到原始价格尺度），所以盘中打开时
  用实时价就地重算位置，不需要重新拉任何历史。
### 「急涨急跌」的口径（改之前先看）

涨速没有现成字段可用，是自己拿分钟线回溯算的：

- **东财 f22 就是涨速**，但 `push2 / push2his` 这条线在本项目两侧都是 TLS 握手
  完成后空响应，整条链路不可用（理由同下面分时那一节）；
- **新浪排行接口 `sort=speed` 不生效**：同一个接口传 `changepercent` 能正确
  排序、传 `speed` 返回的还是代码序，说明后端不认这个字段。

所以 `/api/speed?codes=...` 逐只拉 minline 自己算。四个口径上的决定：

| 决定 | 原因 |
|---|---|
| 回溯用「交易分钟序号」不用数组下标 | 11:30 之后直接跳 13:00，按格回溯 3 格会落到 11:28，把 93 分钟午休的跳空算成 3 分钟 |
| 跨午休的窗口退到午后第一根做基准 | 上午基准 → 下午终点这段的价差是真的，但不是「盘中 3 分钟拉起来」；同时会把午后第一波量算成十几倍放量（实测 512880 在 13:00 那个点 q=14.9）。整段返回 null 又会让 13:00 一过榜单空掉三分钟，所以只让 13:00 这一个点空着 |
| 15:00 那根按 4 分钟折算 | 14:57–14:59 没有连续竞价数据，收盘集合竞价的量全记在 15:00 名下，常是平时一根的 4~10 倍。按 1 分钟算，尾盘会凭空多出十倍放量 |
| 池子 40 只、由前端挑好再传 | 涨速要逐只拉分时，一只一个子请求，Cloudflare 免费计划每请求上限 50。服务端自己筛要先解析 629KB 快照，免费版 10ms CPU 放不下 |

池子的筛选条件：剔除 `bond` / `money` 分组、剔除名称含短融/货币/日利/添益/现金/
理财/保证金/快线的、同指数只留成交额最大的一只，再按当日成交额取前 40。
不这么筛的话，榜首会被科创债和短融 ETF 长期霸占——它们成交额巨大但日内振幅
只有 0.0x%，3 分钟涨速恒等于 0.00%，占着位置没有信息量。

量比 =（最近 N 分钟每分钟成交量）÷（此前 30 分钟每分钟成交量），1.5× 以上标黄。

每行的 20 分钟迷你线，纵向尺度是**全池统一**的一把尺子：取每只「相对 20 分钟前
最大偏离」的 75 分位（夹在 0.06%–0.8%），中间那条虚线就是 20 分钟前的价格。
按每行自己的 min/max 拉满的话，0.18% 的横盘和 0.45% 的急拉画出来一样陡，一列
spark 全是同形状的锯齿——「比例很怪」就是这么来的，而且「谁动得更多」这个信息
也一起丢了。横向同理：名字列固定 168px，走势线才不会因为名字长短一行一行往右挪。

- **因子研究（/research）**：201 个因子的 IC 检验、样本外回测与 PE 策略净值。

### 点开一只标的：分时 / 日 K，两个模式

面板顶部是分段控件，**默认分时**（点开一只，第一反应是「今天怎么了」），
手动切过就记住选择。分时模式下副图/叠加条和周期条隐藏，指标小卡换成日内口径
（日内位置、均价偏离、振幅、分钟点数、成交额）。

分时数据走 `/api/min?code=510300`，Worker 代理新浪 minline，一天 240 个点、
含成交额加权均价，约 7KB，边缘缓存 30 秒一桶。

几个不是「随便画条线」的决定，改之前先看这里：

| 决定 | 原因 |
|---|---|
| 横轴固定 240 格，午休不占位 | 盘中只画已走过的部分，10:30 永远在图中间。按点数铺满会把早盘拉成一条怪线 |
| 价格范围以昨收为中心上下对称 | K 线那套自适应范围在分时上是错的：昨收跑到图边角，一眼分不出此刻涨跌 |
| 刻度按涨跌幅整档（±0.5% / ±1%） | 等分价格区间出来是 4.132 / 4.154 / 4.196 这种读不出意义的数 |
| 量柱上限取 95 分位 | 开盘第一根含集合竞价，常是平时的 4~10 倍；用最大值当刻度会让其余 239 根全部贴地。出界的柱截断并描白边 |
| 填充按昨收线上红下绿 | 而不是「现价涨了整块涂红」——要看的是此刻在基准哪一侧 |

为什么不用东财 trends2：实测裸域名 `push2his/push2.eastmoney.com` 在沙箱和
Worker 两侧都是 TLS 握手完成后空回复，分片域名几十秒内打几次就整体失灵。
新浪这条与全量快照同源（`/api/probe` 里 1718 只稳定返回），链路风险最低。

## 部署形态：Cloudflare 与沙箱版（2026-11-05 新增）

同一份 `worker/src/` 跑在两个地方，页面和 API 完全一致：

| | Cloudflare Worker | 沙箱版（WorkBuddy） |
|---|---|---|
| 入口 | `worker/src/index.js` | `server/app.mjs`（调同一个 fetch） |
| 历史数据 | 回源 GitHub `data` 分支 + 边缘缓存 6h | 读本地 `dist/`（**快 3 个数量级**：单只 K 线 1ms vs 0.7–18s） |
| 自选存储 | KV `etf-board-WATCH` | `server/state/kv/*.json`（原子写） |
| 口令 | `wrangler secret ACCESS_PASS` | `server/.env` 的 `ACCESS_PASS`（自动生成，权限 600） |
| 数据更新 | 天然最新（每次回源） | 每 6h 比一次 commit，变了后台拉（`AUTO_SYNC=0` 可关） |
| 可用性 | 边缘常驻、无冷启动 | 绑沙箱生命周期，**休眠后首次访问要等唤醒** |

### 「以后有变化两边一起改」怎么保证

不靠记性，靠两条硬约束：

1. **业务代码只有一份**。`server/` 里禁止加业务逻辑，只允许「平台能力 → Web 标准接口」的转换。
   要加接口、改前端、调逻辑，一律改 `worker/src/`，两个运行时同时生效。
2. **改动前后各跑一次自检**：

```bash
node server/selftest.mjs                       # 本地：合规扫描 + 12 项接口契约
BASE=https://etf-board.iniestao.workers.dev \
  ACCESS_PASS=xxx node server/selftest.mjs     # 线上：同一套断言打远端
```

合规扫描会拦住 `process` / `Buffer` / `require` / `node:` / 裸 `caches.default` 这类
「只有一边有」的 API——它们能让本地跑得好好的代码在另一边直接 500
（`caches is not defined` 就是这次实测踩到的，已修）。

### 沙箱版怎么跑

```bash
node server/selftest.mjs        # 先确认全绿
PORT=3000 node server/app.mjs   # 起服务；口令在 server/.env 的 ACCESS_PASS
node server/sync-data.mjs       # 手动同步最新 hist（--check 只看状态）
```

**改口令**要两步，少一步不生效：

```bash
# 1. 改 server/.env 里的 ACCESS_PASS
# 2. 重启进程——口令是启动时读进内存的，改文件不会热更新。
#    线上实例由自启动脚本拉起，不能只 kill，得重新发布一次：
node /root/.codebuddy/skills/sites/scripts/publish.js \
  --dir /workspace/etf_board --start-cmd "node server/app.mjs" --language node
```

换口令后所有旧 Cookie 立即作废（Cookie 值本身是 HMAC(口令) 算出来的）。

已发布地址（2026-11-05）：

```
https://etfboardx1.app.workbuddy.host/?sharecode=D2BP5INJ7S
```

两条硬约束，缺一条链接就打不开：

- `?sharecode=` 是**平台层**凭据，每个请求都要带，少了直接 403（不是我们的门禁拦的）。
  所以给别人链接时**必须整条复制**，只发域名会打不开。
- 进去后还要输 `server/.env` 里的 `ACCESS_PASS`，这是我们自己的门禁

域名为什么叫 `etfboardx1` 而不是 `etf-board`：平台的友好域名在**首次发布成功那一刻**
就绑死在这个运行实例上，之后再改 appName 不生效（实测 cancel release 后重发也一样）。
当时试 `etf-board` 返回的是已绑定的旧域名，说明该名字没被接受，`etfboardx1` 是第一个
可用的，也就成了最终域名。这个不可逆——除非换一个全新的运行环境重新首次发布。

打线上做回归要同时给两个：

```bash
BASE=https://etfboardx1.app.workbuddy.host \
SHARECODE=D2BP5INJ7S \
ACCESS_PASS=<server/.env 里的值> \
node server/selftest.mjs
```

线上实测（2026-11-05，收盘后）：

| 项 | 耗时 |
|---|---|
| 首页 230KB | 142ms |
| `/api/hist` 单只 K 线 36KB | 91–142ms（5 次，**稳定**） |
| 未登录 / 错口令 | 401 / 302，门禁正常 |

对比 Cloudflare 版：命中边缘缓存时 50–100ms，但缓存过期或首次访问要回源 GitHub raw，
实测那段是 0.66–18.2s。**沙箱版的优势不是更快，是不再有那个长尾。**

但它是 GBK 且只有 A 股口径。所以走「Worker 代理新浪 + 浏览器直连腾讯自选」的混合。

## 四、历史数据与因子

`data/` 里是 153.8 万条日线（1717 只 × 约 3500 天），已经做过复权和份额折算修正。
`alpha/` 在其上算 56 个技术指标和 101 个 Alpha101 因子，`dist/` 是产物。

> **先读 `docs/FACTORS.md`**。里面有逐条公式和直觉，还有一个不太好看的实测结论：
> 这套因子在 ETF 上样本外失效——训练段夏普 1.61，测试段 −0.71，IC 持续性 0.18。
>
> 所以盯盘页**只放技术指标**（MA/RSI/成交量/波动率这些描述性工具）。
> 101 个因子的全部检验结果单独放在 `/research` 页面——留在那儿是为了有据可查，
> 不是为了让你照着买卖。知道它不能干什么，比知道它能干什么更重要。

**因子值每天重算一次。** Actions 每天 16:35 走完 `compute.py`（56 指标 + 101 因子，
全量重算）后，还会跑 `select_factors.py`（相关性聚类 + 样本外回测，约 33 秒）
和 `tools/gen_research.mjs`，把结果压成 5KB 的 `research.json` 推到 `data` 分支。

页面先用手上内嵌的那份立刻渲染（0ms、断网也能看），再向 `/api/research` 要当天的，
拿到就原地替换。所以打开即有内容，数据也不会停在部署那一天。

只有 17 个精选字段（`HIST_FIELDS`）进了历史二进制，其余因子只存在于这张汇总表里——
Parquet 单个文件 2.27MB，每天全量重传 993MB 没有意义，回测在本地重跑 `compute.py` 即可。

技术上有个硬约束值得记一笔：**Workers 免费版 10ms CPU 解不了 Parquet**（单只 2.27MB、
165 列必然超时）。所以历史数据另导一份精简二进制（近 500 天 × 17 字段，34KB/只），
前端 `DataView` 直接读，不需要 wasm、不需要图表库。

## 五、已知限制

- **免费源没有 SLA**。上游按 IP、按接口粒度风控，随时可能失效。不要作为交易决策的唯一依据。
- **Actions 定时任务会漂移**。GitHub 的 schedule 在高峰期可能延迟几十分钟，历史数据不是准点更新。
- **历史数据默认存在 GitHub 仓库**，62MB，不绑卡。想更快可以换 R2（需绑卡开通，额度内不扣费），代码已支持，改一个变量即可。
- **指数映射会过期**。新 ETF 上市后不在表里，按"无跟踪标的"处理（不去重，不会出错）。
  Actions 每天检查覆盖度，低于 90% 会打 warning。
- 溢价率在跨境 ETF 上才有参考意义（QDII 额度紧张时能冲到 5%+），宽基通常贴近 0。
