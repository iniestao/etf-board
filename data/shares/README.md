# 份额历史（原始层）

ETF 的**每日份额**。份额增加 = 净申购（资金进来），份额减少 = 净赎回。这个目录只存**交易所/数据商披露的份额本身**（单位：份），不存价格、不存净流入金额——那些是派生层的事（`pipeline/gen_shares.mjs` → `dist/shares/`）。

```
data/shares/
  sz_hist.json   772 只 · 265 个交易日 · 1.84 MB   深市（用户导出 Excel，一次性）
  sh_hist.json   928 只 · 265 个交易日 · 2.25 MB   沪市（上交所报表，可随时重抓）
```

日期轴 `2025-10-09 ~ 2026-11-10`，两份完全对齐（同一交易日历），都取自 `sz_hist.json.d`。

## 格式

```json
{
  "v": 1,
  "market": "SZ",
  "unit": "share",
  "src": "深市ETF历史份额.xlsx",
  "imported": "2026-11-11T15:03:00+0800",
  "d": ["2025-10-09", "2025-10-10", "..."],
  "n": { "158000": "港股通金融ETF鹏华" },
  "c": { "158000": [null, 27925835, 27925835, "..."] }
}
```

| 字段 | 说明 |
|---|---|
| `d` | 日期轴，升序，全文件只存一份（避免每只重复 265 个日期字符串） |
| `c[code]` | 与 `d` **等长**的份额数组，整数，单位「份」 |
| `null` | 上市前 / 当日未披露。**不插值、不前向填充**——份额折算、停牌、未上市必须能从 null 里看出来 |
| `n` | 基金名称，仅供排查时认人 |

## 口径与来源

| | 深市 | 沪市 |
|---|---|---|
| 来源 | 用户从行情终端导出的「基金子份额份数」表（`unit_total`） | 上交所 ETF 规模报表 `COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L` |
| 接口 | — | `query.sse.com.cn/commonQuery.do?sqlId=...&STAT_DATE=`（需 `Referer: http://www.sse.com.cn/`） |
| 原始单位 | 份 | 万份（`TOT_VOL`，脚本 ÷1e4 换算） |
| 可回溯 | 只有这一份，**不会再导第二次** | 2023 年起任意交易日，可重抓 |

两份都按**收盘口径**：T 日的份额是 T 日盘后定稿值，不是盘中快照。

> 盘中实时份额不可用。东财 `push2delay` 的 `f38` 实测会在多个快照间抖动（2026-11-11 14:28 三只同时掉 11%~13% 又跳回，且掉到的值对不上任何历史日），那是数据源的问题，不是真实申赎。所以别做实时份额。

## 核对（2026-11-11 实测）

| 检查 | 结果 |
|---|---|
| 深市代码 × 项目清单 | 772 / 772，零缺失零多余 |
| 沪市代码 × 项目清单 | 923 / 947（差的 24 只是货币 ETF，见下） |
| 深市 11-10 份额 vs 东财 `f38`（11-11 实时） | 622 只可比，相对差**中位 0.00%**、最大 1.3% |
| 沪市 11-10 份额 vs 东财 `f38` | 755 只可比，相对差**中位 0.00%**、p90 0.00% |
| 中途缺口（非上市前） | 深市 0 个、沪市 0 个 |
| 净流入折算抽样（2026-11-03） | 1693 只可比，合计 **+808 亿元**（当日大涨，510300 +130 亿、588000 +111 亿，量级合理） |
| 校验和 | `sz_hist.json` sha256:`0802327f1a1b3d05…`、`sh_hist.json` sha256:`3fcd8f816e76bfd2…`（前 16 位） |

**24 只没覆盖的全是货币 ETF**（511600 华安日日鑫、511880 银华日利、511990 华宝添益…）。上交所 ETF 规模报表不含货币 ETF，它们走货币市场基金的披露口径。货币 ETF 份额≈现金等价物，申赎不代表资金进出方向，UI 里显示「-」即可，不必补。

另有 5 只（512390、516480、560000、560650、560890）份额表里有、项目清单里没有——已退市或不在跟踪范围，不影响。

## 怎么更新

```bash
# 深市：以后不会再导 Excel。每日增量由 pipeline/gen_shares.mjs 从东财 f38 采（收盘后），
#       追加到 sz_hist.json 的日期轴上。这份历史是唯一的「过去」。

# 沪市：随时可以重抓，幂等（已有的日期会覆盖成交易所值）
python3 tools/sse_hist.py --date 2026-11-11        # 只补一天
python3 tools/sse_hist.py --days 60                # 补最近 60 个交易日
python3 tools/sse_hist.py --start 2026-01-01       # 从某天起

# 深市：如果又拿到一份新导出的 Excel（比如换了区间）
python3 tools/xlsx2shares.py 新导出.xlsx -o data/shares/sz_hist.json --stats
```

两个脚本都是**幂等 + 原子写**（先写 `.tmp` 再 `os.replace`），跑挂了不会留下半个文件。

`sse_hist.py` 的行为：`STAT_DATE` 回显必须等于请求日才采信（否则视为该日未发布）；返回空结果时重试 4 次（间隔 1.5s 递增）；4 线程并发跑 265 天约 5 分钟；失败的日期在日志末尾列出来，重跑一次即可。

## 已知坑

1. **份额折算会造成非申赎跳变**。深市 265 天里有 160 次单日变动 >50%，多数是真实的大额申购/建仓，但也混着折算。派生层要打 `|Δ|/prev > 30%` 的 warning，弹窗里固定写一句提示，不做自动识别。
2. **同一指数下成员会变**。指数汇总按「当前成员」回溯，历史不重述，UI 要写明「按当前成员合计」。
3. **导出表是转置的**：首列日期、表头两行（名称行 + 代码行）。`tools/xlsx2shares.py` 靠「哪一行能识别出 ≥5 个 6 位基金代码」定位代码行，靠「哪一列日期单元格最多」定位日期列，所以列顺序变了也能解析。单位按中位数量级判定（≥1e7 份 / ≥1e3 万份 / 否则亿份），判定结果打在 `--stats` 日志里。
