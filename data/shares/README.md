# 份额历史（原始层）

ETF 的**每日份额**。份额增加 = 净申购（资金进来），份额减少 = 净赎回。这个目录只存**交易所/数据商披露的份额本身**（单位：份），不存价格、不存净流入金额——那些是派生层的事（`pipeline/gen_shares.mjs` → `dist/shares/`）。

```
data/shares/
  sz_hist.json   772 只 · 265 个交易日 · 1.84 MB   深市（用户导出 Excel，一次性）
  sh_hist.json   928 只 · 265 个交易日 · 2.25 MB   沪市（上交所报表，可随时重抓）
```

日期轴 `2025-10-09 ~ 2026-11-10`，两份完全对齐（同一交易日历），都取自 `sz_hist.json.d`。

## 格式

```json
{
  "v": 1,
  "market": "SZ",
  "unit": "share",
  "src": "深市ETF历史份额.xlsx",
  "imported": "2026-11-11T15:03:00+0800",
  "d": ["2025-10-09", "2025-10-10", "..."],
  "n": { "158000": "港股通金融ETF鹏华" },
  "c": { "158000": [null, 27925835, 27925835, "..."] }
}
```

| 字段 | 说明 |
|---|---|
| `d` | 日期轴，升序，全文件只存一份（避免每只重复 265 个日期字符串） |
| `c[code]` | 与 `d` **等长**的份额数组，整数，单位「份」 |
| `null` | 上市前 / 当日未披露。**不插值、不前向填充**——份额折算、停牌、未上市必须能从 null 里看出来 |
| `n` | 基金名称，仅供排查时认人 |

## 口径与来源

| | 深市 | 沪市 |
|---|---|---|
| 来源 | 用户从行情终端导出的「基金子份额份数」表（`unit_total`） | 上交所 ETF 规模报表 `COMMON_SSE_ZQPZ_ETFZL_XXPL_ETFGM_SEARCH_L` |
| 接口 | — | `query.sse.com.cn/commonQuery.do?sqlId=...&STAT_DATE=`（需 `Referer: http://www.sse.com.cn/`） |
| 原始单位 | 份 | 万份（`TOT_VOL`，脚本 ÷1e4 换算） |
| 可回溯 | 只有这一份，**不会再导第二次** | 2023 年起任意交易日，可重抓 |

两份都按**收盘口径**：T 日的份额是 T 日盘后定稿值，不是盘中快照。

> 盘中实时份额不可用。东财 `push2delay` 的 `f38` 实测会在多个快照间抖动（2026-11-11 14:28 三只同时掉 11%~13% 又跳回，且掉到的值对不上任何历史日），那是数据源的问题，不是真实申赎。所以别做实时份额。

## 核对（2026-11-11 实测）

| 检查 | 结果 |
|---|---|

| 沪市代码 × 项目清单 | 923 / 947（差的 24 只是货币 ETF，见下） |
| 深市 11-10 份额 vs 东财 `f38`（11-11 实时） | 622 只可比，相对差**中位 0.00%**、最大 1.3% |
| 沪市 11-10 份额 vs 东财 `f38` | 755 只可比，相对差**中位 0.00%**、p90 0.00% |
| 中途缺口（非上市前） | 深市 0 个、沪市 0 个 |
| 净流入折算抽样（2026-11-03） | 1693 只可比，合计 **+808 亿元**（当日大涨，510300 +130 亿、588000 +111 亿，量级合理） |
| 校验和 | `sz_hist.json` sha256:`0802327f1a1b3d05…`、`sh_hist.json` sha256:`3fcd8f816e76bfd2…`（前 16 位） |

**24 只没覆盖的全是货币 ETF**（511600 华安日日鑫、511880 银华日利、511990 华宝添益…）。上交所 ETF 规模报表不含货币 ETF，它们走货币市场基金的披露口径。货币 ETF 份额≈现金等价物，申赎不代表资金进出方向，UI 里显示「-」即可，不必补。

另有 5 只（512390、516480、560000、560650、560890）份额表里有、项目清单里没有——已退市或不在跟踪范围，不影响。

## 派生层：`dist/shares/`（`pipeline/gen_shares.mjs`）

清单里那一列和点击后的柱状图读的是这里，不是原始层。

```
dist/shares/
  last.json        104 KB   {d, ax, c:{份额亿份}, f:{当日净流入亿元}, ix:{指数名}}
  <code>.json      1.5 KB   {c, n, s, v:[250 天净流入], cv:{下标:折算乘子}}
  ix.json          312 KB   {d, ax, ix:{指数名:{v:[每日汇总], n:成员数}}}
```

```bash
node pipeline/gen_shares.mjs            # 用现有份额算
node pipeline/gen_shares.mjs --fetch    # 先抓当日份额（收盘后跑，CI 走这条）
node pipeline/gen_shares.mjs --dry      # 只打印统计
```

**核心公式**：

```
净流入_t = (S_t − S_{t−1} × k_t) × close_t / 1e8     单位：亿元
```

`k_t` 是当日折算份额乘子（无折算 = 1）。不修正的话，265 天里有 86 次折算，会凭空多出 **5784 亿元**的假申购（占全市场流量的 7.6%），单次最高 529 亿。

`k` 的两个来源：

| 来源 | 说明 |
|---|---|
| `etf_adjust`（`kind='split'`） | 174 次历史折算，`step` 就是 k。**日期要往前挪一个交易日**——份额 T 日盘后登记，价格 T+1 才跳空，表里记的是 T+1 |
| 价格反推 | `|ΔS|>22%` 且「份额倍数 × 次日价格跳空 ≈ 1」（误差 <15%）→ 判定折算，`k = ΔS 倍数` |

价格反推实测抓出 86 次，与 `etf_adjust` 重合 78 次，剩下几次是表里还没有的新事件。判据不会误伤真实大额申赎：516190 在 2026-01-12 份额 ×9.0，但次日价格只跌 3.7%，乘积 8.67 —— 一眼是真申购。

**三个边界**：

1. 小于 22% 的折算检测不到，靠 `etf_adjust` 兜底（实测这 265 天的折算全是 1.9~6 倍的净值归一）。
2. 最新一天没有「次日价格」，当天的折算判定要等下一个交易日；跑的时候会打印「另有 N 处份额跳变缺次日价格」。
3. 折算日的价格用 T 日（旧净值）。修正后 ΔS 接近 0，价格用哪天都是噪声级差异。

### 页面上怎么用

清单第 12 列「申赎」（`worker/src/page.js` 的 `shCell()`）：

| 状态 | 显示 | 说明 |
|---|---|---|
| 同指数去重、未展开 | 该指数全部成员**合计**，数字后带灰色「合」胶囊 | 份额跨基金不能相加，所以合计只能是金额 |
| 点 ×N 展开某个指数 | 该只**单只**值 | 展开后每行就是一只，回到单只口径 |
| 关掉「同指数去重」 | 单只 | 列表里每只 ETF 都在，没有「代表」这一说 |

点数字弹窗：250 个交易日每日柱状图，红=净申购、绿=净赎回；折算日柱子顶上有一个黄色小圆点；竖线 + 悬浮气泡给单日数值；底部是最新一日 / 近 20 日 / 近 250 日累计和申赎天数。

数据两个请求：`/api/shares`（`last.json`，约 100KB，先画）和 `/api/shares?ix=1`（`ix.json`，约 310KB，去重行的合计要靠它）。单只弹窗再按需取 `/api/shares?code=`（1.5KB）。

**自检**（每次跑都会打，失败则 `exit 1`）：

- 510300 份额在 100~2000 亿份之间
- 末日净流入覆盖率 ≥ 90%（低于这个数多半是新浪当天 K 线没补全，第二天再跑）
- 抽两个指数重算成员和，与 `ix.json` 对齐
- 折算日不该再有「> 30 亿元且 > 该只规模 60%」的残留

## 怎么更新

```bash
# 深市：以后不会再导 Excel。每日增量由 pipeline/gen_shares.mjs 采（收盘后），
#       追加到 sz_hist.json 的日期轴上。这份历史是唯一的「过去」。

# 每日抓取的源与退路（都写死在 gen_shares.mjs 里）：
#   深市  东财 f38  →  失败则深交所 1945 报表的 dqgm（78 页 / 772 只，约 45 秒）
#   沪市  上交所 STAT_DATE  →  失败则东财 f38
# 深市之所以要有第二源：它断一天就再也补不回来。沪市不一样，随时能用
# sse_hist.py 按 STAT_DATE 回查历史。

# 沪市：随时可以重抓，幂等（已有的日期会覆盖成交易所值）
python3 tools/sse_hist.py --date 2026-11-11        # 只补一天
python3 tools/sse_hist.py --days 60                # 补最近 60 个交易日
python3 tools/sse_hist.py --start 2026-01-01       # 从某天起

# 深市：如果又拿到一份新导出的 Excel（比如换了区间）
python3 tools/xlsx2shares.py 新导出.xlsx -o data/shares/sz_hist.json --stats
```

两个脚本都是**幂等 + 原子写**（先写 `.tmp` 再 `os.replace`），跑挂了不会留下半个文件。

`sse_hist.py` 的行为：`STAT_DATE` 回显必须等于请求日才采信（否则视为该日未发布）；返回空结果时重试 4 次（间隔 1.5s 递增）；4 线程并发跑 265 天约 5 分钟；失败的日期在日志末尾列出来，重跑一次即可。

> **为什么两份文件是「每只一行」的 JSON**：它们住在 main 分支上，每天追加一格。写成单行 JSON 的话，每次 commit 都是一个 2 MB 的整 blob；每只一行时 git 的 delta 压缩只存每行末尾多出来的几个字节。


## 已知坑

1. **份额折算会造成非申赎跳变**。深市 265 天里有 160 次单日变动 >50%，多数是真实的大额申购/建仓，但也混着折算。派生层要打 `|Δ|/prev > 30%` 的 warning，弹窗里固定写一句提示，不做自动识别。
2. **东财对云 IP 会整段拒连**。2026-11-11 那天 Actions 上东财 25 页全挂（连名单都只剩
   1023 只）、本地跑了几十次后被临时封 IP（`Empty reply from server`）。所以凡是用东财的
   地方都得有第二源或熔断，不能假设它一直可用。
3. **同一指数下成员会变**。指数汇总按「当前成员」回溯，历史不重述，弹窗脚注里写了这一句。所以「近 250 日累计」是「今天这 17 只加起来」的累计，不等于当年那份披露口径。
4. **导出表是转置的**：首列日期、表头两行（名称行 + 代码行）。`tools/xlsx2shares.py` 靠「哪一行能识别出 ≥5 个 6 位基金代码」定位代码行，靠「哪一列日期单元格最多」定位日期列，所以列顺序变了也能解析。单位按中位数量级判定（≥1e7 份 / ≥1e3 万份 / 否则亿份），判定结果打在 `--stats` 日志里。
